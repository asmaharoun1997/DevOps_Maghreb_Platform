Maghreb Platform sur Kubernetes

L'architecture du sujet « mise en production d'une application e-commerce sur Kubernetes », avec ton site à la place de WordPress. En haut, ce qui existe physiquement (les machines Azure). En bas, ce que Kubernetes fait tourner dessus.

À l'intérieur du namespace, le site joint la base par le nom mysql:3306 : c'est le Service ClusterIP qui donne ce nom stable, même si le pod MySQL redémarre et change d'adresse.

Points d'attention

  • Le nom du namespaceKubernetes refuse le tiret bas : mon_nom-project1 tel quel ne passe pas. Utilise des minuscules, chiffres et tirets, par exemple asma-project1.
  • Docker et kubeadmDepuis Kubernetes 1.24, kubelet ne parle plus directement à Docker. On installe Docker (ou seulement containerd) et kubelet utilise containerd. Docker reste utile sur le poste de contrôle pour construire l'image.
  • Taille des VMkubeadm exige au moins 2 vCPU et 2 Go de RAM sur le master : Standard_B2s (4 Go) convient. Prometheus, Grafana et Loki consomment beaucoup de mémoire : si les workers saturent, passe-les en Standard_B2ms (8 Go). Vérifie ton quota de vCPU avant.
  • Pourquoi gitlab.com et pas GitLab dans le clusterLe runner ne prend qu'environ 100 Mo, le dépôt survit à la fin du compte Azure et le pipeline reste disponible même si le cluster est en panne. Les jobs s'exécutent quand même dans tes pods : la démo montre le CI/CD tourner dans ton cluster.
  • Le jeton du runnerLe jeton d'enregistrement du runner (créé dans gitlab.com, menu CI/CD > Runners) est un secret : il va dans Ansible Vault ou un Secret Kubernetes, jamais en clair dans le dépôt.
  • Le NFS est un point uniqueSi worker2 tombe, les volumes ne sont plus accessibles. C'est ce que demande le sujet ; mentionne-le dans le rapport avec l'amélioration possible (stockage managé Azure Files).
  • MySQL reste à 1 réplicaSeul le site se met à l'échelle. Une base ne se duplique pas avec kubectl scale : il faudrait une réplication MySQL, hors du périmètre du sujet.
  • Les photos et les réplicasLes 3 pods du site doivent voir les mêmes photos : d'où le volume NFS en ReadWriteMany monté sur /data/media, avec STORAGE_LOCAL_DIR=/data/media.
  • Ouvertures réseauLe NSG n'ouvre SSH qu'à ton IP. Le port 6443 aussi, si tu pilotes kubectl depuis ton PC. Les ports 30080 (site) et 30300 (Grafana) sont ouverts au public. Extension possible : Ingress + HTTPS au lieu des NodePorts.
